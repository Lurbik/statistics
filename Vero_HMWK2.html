0. Scope and explicit assumptions

This laboratory performs didactic cryptanalysis on synthetic keys and texts generated locally in the browser: no real wallets, credentials, external targets, or network connections are used. In Homework 1, the relation Q = kG was illustrated on the small prime field curve y² = x³ + 7 (mod 17) with G = (1, 5), k = 6, Q = (5, 8). That toy curve is not the real secp256k1 curve, and Q = kG defines public-key derivation rather than an encryption algorithm. Here we use the official 256-bit secp256k1 domain parameters and make the ECC key-recovery experiment feasible only by restricting the private key k to a small interval 1…B.

  • Didactic encryption choice: because the assignment prompt does not mandate a specific ECC encryption standard, we explicitly adopt didactic per-byte EC ElGamal. It must not be confused with "Ethereum encryption", hybrid ECIES, or ECDSA signatures.
  • Two distinct moduli: curve point coordinates (x, y) are reduced modulo the field prime p; scalars (private key k and ephemeral nonces r) are reduced modulo the group order n.
  • Long-term key vs ephemeral secret: in this lab, only the recipient's private key k is restricted to 1…B (whereas in a full deployment k is drawn uniformly from 1…n−1). Each byte's ephemeral scalar r is drawn uniformly from the full range 1…n−1 via crypto.getRandomValues with rejection sampling, making accidental nonce collisions negligibly likely and avoiding a deliberately small-r interval.
  • Strict attacker boundary: the Caesar attack receives only the ciphertext and the corpus language model; the ECC key-recovery routine receives only public parameters (G, Q, B_search) and never accesses k, r, S, plaintext, or DOM fields.

2. ECC encryption — didactic EC ElGamal on secp256k1

What this shows: anyone holding the public key Q can encrypt; only the holder of the matching private key k can remove the mask; fresh per-byte randomness r yields different ciphertexts every time the same message is encrypted.

Official secp256k1 parameters (SEC 2 v2): curve y² = x³ + 7 (mod p) with a = 0, b = 7, prime field modulus p = 2²⁵⁶ − 2³² − 977, and base point G of prime order n. All arithmetic uses JavaScript BigInt.

Byte-to-point reversible encoding vs encryption

Each byte value b ∈ {0…255} (in our demo, printable ASCII bytes 32–126 from the normalized message) is mapped to the curve point M_b = (b + 1)·G using a public, precomputed 256-entry table. This mapping is a reversible encoding, not encryption: anyone can invert it by table lookup. Encryption masks M_b with an ephemeral shared point S = rQ:

Key generation: k ∈ {1…B_key}, Q = kG Encrypt byte b: pick uniform r ∈ {1…n−1}, R = rG, S = rQ, C = M_b + S → ciphertext pair = (R, C) Decrypt (R, C): compute kR = k(rG) = r(kG) = rQ = S, recover M_b = C − kR, table-lookup byte b from M_b

The recipient generates a local key pair (k_local, Q_local) and can decrypt any active ciphertext whose public key Q matches Q_local. Importing a public JSON file does not overwrite k_local.

Why this toy construction is not for production: (1) Ciphertext expansion: each plaintext byte is encrypted into two curve points—normally four 32-byte coordinates (128 raw coordinate bytes per plaintext byte; 130 bytes in uncompressed SEC 1 encoding with 0x04 prefixes, 66 bytes in compressed SEC 1 encoding, and even more in hex-JSON). The exceptional point at infinity has no coordinates and occupies one byte in SEC 1 encoding; (2) Lack of authentication / malleability: there is no integrity check to detect tampering (for instance, replacing C with C + mG shifts the decoded point to (b+1+m)G, which decodes to byte b+m whenever 0 ≤ b+m ≤ 255, or fails table lookup otherwise), and message length is leaked; (3) Small key range in this lab: restricting k to 1…B allows trivial key recovery (Section 6).

4. Language corpus & statistical cryptanalysis of Caesar

What this shows: because a shift only cyclically relabels A–Z, comparing candidate decryptions against an English corpus model recovers the shift automatically.

The built-in training corpus is synthetic English prose written for this laboratory (over 11,500 A–Z letters across varied topics). Because it is synthetic, its empirical distribution reflects this specific text rather than a universal natural-language benchmark. You can paste any custom corpus or load a local .txt file; all frequencies are computed dynamically from the loaded corpus.

Unified letter-preparation convention (lettersOnly): both unigram counts and adjacent bigram pairs are extracted from lettersOnly(text), which upper-cases the text and keeps exclusively A–Z (so consecutive letters across word boundaries form bigrams consistently in corpus training, candidate scoring, and Section 5 window sampling). Decrypted previews retain spaces and punctuation for readability.

Goodness-of-fit via Chi-squared (with additive smoothing α = 0.5)

To prevent division by zero when a corpus omits rare letters, we apply additive smoothing with α = 0.5 (add-half smoothing) over the 26 letters:

f_i = (count_i + 0.5) / (T + 26 × 0.5) where T = total A–Z letters in corpus, Σ_i f_i = 1

Given a ciphertext with N letters, for each candidate shift s ∈ {0…25} we decrypt the text, count the observed occurrences O_i(s) of each letter i ∈ {0…25}, and compute:

χ²(s) = Σ_{i=0..25} [ (O_i(s) − N·f_i)² / (N·f_i) ]

Interpretation: lower χ²(s) indicates closer agreement with the corpus letter profile. It is a goodness-of-fit ranking score, not a calibrated probability of correctness. We also compare two optional alternatives on the same lettersOnly stream: Bigram (2-gram) log-likelihood (requires N ≥ 2 letters; returns insufficient data for N < 2) and the Most-common-letter → E heuristic. Across all three methods, a candidate shift is counted as a unique estimate only when there is no tie within numerical tolerance (10⁻⁹).

Receives only the ciphertext and the active language model.

6. Attacking the restricted ECC key space

What this shows: recovering the private key k in O(B) curve additions using exclusively the public generator G and the target public key Q, then decrypting the snapshotted ciphertext.

The attacker receives (G, Q, ciphertext, B_search). Starting from P_1 = G, it steps incrementally (P_{j+1} = P_j + G) without recomputing jG from scratch:

P = O ; for j = 1, 2, …, B_search: P ← P + G ; if P == Q return j

Generate a key and encrypt (or import) a ciphertext first.

Comparison with Caesar's statistical attack & full-range ECC security: Caesar's attack is probabilistic and depends on message length and language conformity. In contrast, the ECC key search is algebraic and exact: jG = Q is a deterministic mathematical condition that requires no language model and works even on a 1-byte ciphertext (or on Q alone). In a properly configured secp256k1 system where k is drawn uniformly from 1…n−1 (n ≈ 2²⁵⁶), this exhaustive search still exists mathematically, but its complexity becomes computationally infeasible: linear scan costs O(n), and generic discrete-logarithm algorithms (Baby-Step Giant-Step, Pollard's rho) require on the order of √n ≈ 2¹²⁸ group operations (~128 bits of classical security against key recovery via ECDLP, while semantic security of ElGamal ciphertexts under passive eavesdropping relies on the Decisional Diffie-Hellman (DDH) assumption in the group).

8. Alternative attacks & separation of weaknesses

  • Caesar alternatives: Exhaustive inspection of all 26 shifts is trivial for a human reader; χ² automates that ranking using all 26 unigram frequencies. The Most-common-letter → E heuristic uses only the single mode of the histogram and is easily misled on short samples or when T, A, O outnumber E (or when multiple letters tie for the maximum count). Bigram log-likelihood scores consecutive letter pairs, leveraging sequential transition structure, though on small or atypical samples neither unigram χ² nor bigrams is guaranteed to dominate in every single instance.
  • ECC interval algorithms: When k ∈ {1…B}, Baby-Step Giant-Step (BSGS) reduces time to O(√B) using O(√B) stored points, and Pollard's Kangaroo achieves O(√B) expected time with small memory.
  • Weaknesses from restricted key space vs toy protocol design vs hypothetical implementation flaws:
    • Restricted key space (k ∈ 1…B, present in this lab): directly enables O(B) private-key recovery from Q = kG. Choosing k uniformly in 1…n−1 makes key recovery computationally infeasible.
    • Toy scheme design limitations (present even if k is chosen in 1…n−1): (a) no authentication / malleability—tampering is not reliably detected; adding mG to C shifts the decoded point to (b+1+m)G, which decodes to b+m whenever 0 ≤ b+m ≤ 255 (or triggers a table-lookup error if outside 0…255); (b) message length is observable; (c) high bandwidth overhead (two curve points per plaintext byte).
    • Hypothetical nonce-reuse flaw (not deliberately introduced here; fresh independent draws make accidental reuse negligibly likely): if an implementation reused the same r across two bytes, the masks S = rQ would be identical and C_1 − C_2 = (b_1 − b_2)G would immediately leak the byte difference.

What this experiment establishes

Both ciphers allow a reversible transformation of the same message. Caesar keeps the language statistics under a fixed alphabet shift, so a corpus can rank likely keys. EC ElGamal uses fresh random masks, but restricting the recipient key to a small interval still permits exact recovery from Q = kG. A visually random ciphertext and a high empirical entropy do not by themselves establish cryptographic security.
